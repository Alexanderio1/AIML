# Лабораторная № 1: линейная регрессия и PCA

Выполненная работа на **Appliances Energy Prediction**: исследование данных,
корреляции и VIF, OLS/Lasso/Ridge до и после PCA, вложенная кросс-валидация,
RMSE/R²/MAPE, остатки и дополнительная проверка по времени.

Основной отчёт — **[lab1.ipynb](lab1.ipynb)** с сохранёнными результатами и
содержательными markdown-пояснениями после каждой вычислительной ячейки.
**[report.html](report.html)** можно открыть в браузере без Python;
графики и результаты встроены, для красивого отображения формул MathJax
может потребоваться Интернет. Автор, группа и преподаватель не выдуманы:
их можно добавить перед сдачей.

## Состав проекта

- `lab1.ipynb` — выполненный notebook и полный отчёт на русском.
- `report.html` — HTML-версия, включая код.
- `lab1.py` — полный исполняемый листинг кода из notebook.
- `data/energydata_complete.csv` — исходные 19 735 измерений, не синтетические данные.
- `data/source.json` — происхождение, коммит источника и SHA-256.
- `results/metrics_all.csv` — итоговое сравнение шести моделей; MAPE в процентах.
- `results/metrics_pca_minus_original.csv` — изменения после PCA.
- `results/metrics_temporal.csv` — отдельная временная проверка.
- `results/figures/` — рисунки; остальные CSV — корреляции, VIF, PCA, остатки и настройки.
- `scripts/` — загрузка с проверкой суммы, сборка и выполнение notebook.

## Повторный запуск (Python 3.12)

Локальный CSV уже включён, поэтому Kaggle API и токен не требуются.
Фактически использован оригинальный CSV из GitHub-репозитория автора
исследования, а не скачанный архив Kaggle. Ссылки на оба ресурса есть в отчёте.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --prefix "$VIRTUAL_ENV" --name aiml --display-name "Python (AIML)"
python scripts/fetch_data.py
python scripts/run_notebook.py
python scripts/validate_artifacts.py
```

Все команды запускаются из корня проекта. Ожидается выполнение на CPU;
нейросети, GPU, внешние сервисы и обучение по сети не нужны.
Для интерактивного просмотра откройте `lab1.ipynb` в Jupyter/VS Code и выберите
окружение с установленными зависимостями. Отдельный веб-сервер для расчётов не нужен.

Только расчёты и PNG/CSV без обновления HTML и пояснений notebook:

```bash
python lab1.py
```

`scripts/build_notebook.py` пересоздаёт notebook из исходного шаблона и **сбрасывает
его выводы**; после него обязательно выполните `scripts/run_notebook.py`.
Для повторного экспорта уже выполненного notebook без пересчёта:
`python scripts/run_notebook.py --export-only`.

## Методика и ограничения

Основное разбиение 80/20, `random_state=42`. На train — вложенная CV 5×3;
стандартизация и PCA заново обучаются внутри фолдов. Число компонент —
не менее 95% объяснённой дисперсии, без подбора по тесту. Модель выбирается
по внешнему CV RMSE. Исходные данные не содержат пропусков; `dropna` ничего
не удаляет. `rv1` и `rv2` — одинаковые случайные контроли, исключённые по описанию.
Из даты созданы четыре циклических календарных признака.

Случайное разбиение временного ряда оценивает интерполяцию внутри наблюдаемого
периода. Проверка на последних 20% с `TimeSeriesSplit` и суточным разрывом
показывается отдельно. Даже она предполагает известность одновременных
температур, погоды и `lights`, поэтому не является прогнозом за сутки вперёд.
Высокие MAPE и ошибки на пиках не скрыты. Ортогональность PCA не означает,
что качество регрессии должно улучшиться. Подробнее — в выводах отчёта.
